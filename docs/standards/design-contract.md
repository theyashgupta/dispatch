# Design Contract — Console Grade

**Console Grade** is Dispatch's chrome treated as an instrument panel for live agent sessions:
every piece of on-screen text and every container has an explicit rank and is styled to occupy
it. Density stays tight wherever scanning matters — the board, cards, and the sync strip keep
their current tightness because that density is load-bearing for the at-a-glance requirement —
while the two surfaces a person actually reads, the detail panel body and modal body, get more
typographic room. This document is the single source of visual direction for the current
milestone; every later UI pass derives from it and this document wins on any conflict.

## References

| Product          | What it does that Dispatch does not                                                                                                                                                                    |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Linear           | Ships a disciplined 3-value radius vocabulary tied to element role rather than one flat radius everywhere, and reserves its accent color for exactly three jobs, never letting it drift into a fourth. |
| Raycast          | Uses a distinct 500 (Medium) weight as a real typographic step between regular and semibold, and its radius genuinely scales with element size instead of being purely decorative.                     |
| Warp             | Treats monospace as a separate typographic voice with its own sizing rule, not merely "the same copy in a different font."                                                                             |
| Vercel dashboard | Runs a compact top strip rather than a tall, marketing-scale header, keeping chrome subordinate to content.                                                                                            |

Arc, Superhuman, and Things are cited only as lower-confidence directional color for the accent
discipline and terse-surface feel — their exact numeric values were not independently verified
and are not the source of any fixed value below.

The Linear, Raycast, and Warp numbers referenced above come from published token extractions of
their public marketing sites, not their authenticated product UIs, so they are directional, not
literal targets. Every fixed value in this contract is Dispatch's own, checked against Dispatch's
own rendered content — never copied from these products.

The vocabulary is tied to element ROLE, expressed as a height threshold a reader can apply: an
element up to roughly 19–27px tall (a chip or badge) takes `--radius-sm`; an element from there up
to roughly 200px tall (buttons, inputs, cards, columns) takes the workhorse `--radius`; an element
200px tall or taller, or a dismissible floating menu sharing the modal's `--shadow-float`
elevation treatment (the modal dialog, the search dropdown, `MoveToPicker`), takes `--radius-lg`.
The vocabulary deliberately does not reach resize handles or the scrollbar thumb — radius there is
decoration with no hierarchy payoff, and the existing scroll-gutter and scrollbar handling in
`tokens.css` is hard-won and is not touched. Not reaching them is not the same as their rendering
square: the thumb inherits `var(--radius)` from that untouched block and measures 6px, as the
`radius-scope` row above records. (The line range this paragraph used to cite for the scroll-gutter
block went stale as `tokens.css` grew; the block is cited by name now so it cannot go stale again.)

The surface ladder stays exactly as it is: `--bg` / `--surface-column` / `--surface-card` /

Phase 84 shipping the picker and the carousel overlay as additional consumers. At-rest cards and
columns keep no shadow — confirmed via live measurement that an at-rest card's own `boxShadow`
computes to `none` at every breakpoint.

## Motion

Nothing changes. Enter and exit transitions stay 150ms ease-out, `prefers-reduced-motion` is
respected globally by `tokens.css`'s `prefers-reduced-motion` block, and nothing animates on hover. This is already correct:
"polish" is not a license to add motion, and no value in this contract introduces any.

## Card identity

Per-column visual identity is limited to attention only: Needs Input gets a distinguishing
treatment; every other column's cards stay visually terse. The board's core value is reliably
showing which tickets need human attention, and per-column identity everywhere would spend
scanning density on information the column header already carries.

## Component library — DECISIVE

**Ratified:** keep the hand-rolled `tokens.css` plus inline `style` object approach. Tailwind and
shadcn are not adopted for this milestone.

Three reasons. First, every audit finding behind this milestone is a design decision that was
never made — an inconsistent radius, an under-used weight tier, a copy-pasted shadow — rather than
a limitation of the delivery mechanism; Linear, Raycast, and Warp all express their own systems as
bespoke CSS custom properties too, so the mechanism was never the gap. Second, shadcn's own
unmodified defaults carry a recognizable generic signature of their own, so adopting it risks
trading one generic look for another rather than buying a genuinely distinct one. Third, migrating
every component in `src/web/primitives/` and `src/web/features/` for zero functional change is the
same diff-churn trade `frontend-design-system.md`'s `## Styling approach — DECISIVE` section
already rejected for CSS Modules, vanilla-extract, and styled-components — made larger here, and in
a repo with no test code, where verification is a smoke-tester exercising the running app rather
than a suite that could catch a regression automatically.

Honest caveat: a future milestone that wants a genuinely different visual language —
illustration, marketing surfaces, a public-facing site — would make Tailwind defensible. This
ratification is scoped to the current milestone and is not permanent.

## What this does NOT change

This section exists so later phases cannot quietly expand scope beyond what this contract fixes.

- The terminal.
- Motion (see `## Motion` above).
- The surface-ladder elevation approach (see `## Elevation` above).
- The semantic `--prio-*`, `--col-*`, and `--status-*` palettes.
- All behavior.
- The mobile carousel.
- Touch drag activation constraints.
- Coarse-pointer resize handles.
- The detail panel's history-based back-button takeover on narrow viewports.
- The no-spinner optimistic board contract.
- Column and panel resize with persisted widths.
- The existing aria wiring, including `aria-expanded`, `aria-live="polite"` on sync status, and
  `aria-pressed` on the view toggles.
- The focus-visible-only gating of focus rings.
- The `Notice` / `Field` / `Modal` primitive contracts — their props, structure and behaviour. This
  exemption is about the primitives' API, not a freeze on the tokens they resolve: a primitive whose

- The existing scroll-gutter and `::-webkit-scrollbar` handling in `tokens.css`.

## How values were checked

Every value above was checked against real rendered content, not derived on paper. An isolated,
disposable instance of the app was seeded with realistic cards — short and long titles, several
with full multi-paragraph markdown descriptions, spread across all six board columns — and booted
independently of the live board. Each candidate value was applied as a runtime CSS custom-property
override against the real running app (never a source edit), then viewed at four breakpoints
(>=1600px, 1024-1599px, 768-1023px, and below 768px on named real-device viewport presets) against
real card titles, real panel copy, and real modal copy, with screenshots and, for interaction-gated
values like the focus ring, real keyboard and pointer input rather than synthetic focus calls. The
row-count measurements behind the SyncStrip height read every input — viewport height, strip
height, column-header height, card height, and the inter-card gap — live from the rendered page,
never as a hardcoded literal. Wherever a checked value disagreed with a starting candidate, the
checked value won and the disagreement is recorded above as a one-line deviation note.
