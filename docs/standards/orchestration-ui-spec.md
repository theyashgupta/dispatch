# Orchestrator UI Spec

Status: accepted. Date: 2026-10-06. Ticket: LOCAL-84. Design records: `docs/standards/orchestration-design.md` (cited as D-1 to D-9).

This spec is the screen contract for the UI tickets LOCAL-85 to LOCAL-93. It gives the routes, the layout at each width, the parts with their primitives and copy, and the empty, loading, error and stale states of each screen. A UI ticket follows this spec. A change to this spec is a new dated entry in this file.

Terms: "orchestrator" is the Claude session that belongs to a board. "Supervisor" is the server code that watches the sessions. The session start saga keeps the name "orchestration" (term rule in the glossary of the design records).

Table rules:

- In a parts table, the primitive cell names a file in `src/web/components/ui/` in a code span. "Added by the UI ticket" means that the UI ticket adds the primitive with `npx shadcn@latest add`. "Module component" means plain elements with token classes inside a module. Only the group progress bar uses it. Frontend rule 10 allows plain elements only in the allowed custom families, so LOCAL-92 adds the segmented progress bar to "Allowed custom families" in `docs/standards/frontend-architecture.md` in the same change (U2-07).
- Layout widths: the 1440 px rules apply at 1280 px and wider. The 1024 px rules apply from 768 px to 1279 px. The 390 px rules apply below 768 px.
- In a states table, each screen has the rows Empty, Loading, Error and Stale. Stale means that the board stream is disconnected and the screen shows the last data that it received.

## Information architecture

### Routes

- The routes of today stay. Each URL of today shows the default board `LOCAL`, as today.
- Each board-scoped route takes the search parameter `board` with the board key. When the parameter is absent, the route shows the default board (D-4). The board-scoped routes are the pages that read the board snapshot today: `/board`, `/inbox`, `/today`, `/tickets`, `/sessions`, `/workspace`, `/workspaces`, `/flow`, `/activity`, `/archive`, and the new `/dashboard`. The source pages (`/pull-requests`, `/errors`, `/slack`, `/meetings`, `/calendar`) read only the global source data or look up cards. They keep the `board` parameter in their links and open the cards of the selected board.
- The selected board is the `board` parameter of the current URL. A link inside the app keeps the `board` parameter of the current URL.
- An unknown or archived `board` key shows the default board `LOCAL` and the toast "Board <KEY> is not available." When the user archives the selected board, the app goes to the same page on the default board.
- New route `/boards`: the boards page (Screen 1). It is not board-scoped.
- New route `/dashboard`: the dashboard of the selected board (Screen 4).
- The orchestrator panel (Screen 3) is a right panel on the `/board` route. The search parameter `panel=orchestrator` opens it, so a link can open it. At 1440 px and 1024 px it is a `resizable` panel beside the columns. The board header button "Orchestrator" toggles the panel, and its close button closes it at every width. At 390 px it is a `sheet` from the right edge.
- The ticket detail panel stays as today: a fixed right panel above the page. When the user opens a card while the orchestrator panel is open, the detail panel covers the orchestrator panel. Escape closes the detail panel first.

### Where each screen lives

| Screen                        | Route or place                                       | How the user gets to it                                                                                                                                                                   |
| ----------------------------- | ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Boards page                | `/boards`                                            | The command palette entry "Manage boards". The switcher menu item "Manage boards" when the switcher shows.                                                                                |
| 2. Board switcher             | The sidebar header, below the wordmark               | It shows only when more than one board exists (not archived). The shortcut `b`. The command palette entries "Switch to board <name>".                                                     |
| 3. Orchestrator panel         | The right panel of `/board?panel=orchestrator`       | The board header button "Orchestrator" when the board has a main orchestrator, else "Add orchestrator" (Screen 5).                                                                        |
| 4. Dashboard                  | `/dashboard?board=<KEY>`                             | The sidebar row "Dashboard" in the Work group. The row shows only when the selected board has a main orchestrator. The command palette entry "Go to Dashboard" shows under the same rule. |
| 5. Board with no orchestrator | `/board` when the selected board has no orchestrator | The sidebar row "Board", as today.                                                                                                                                                        |

Navigation rules:

- With one board and no orchestrator, the shell is the shell of today. It shows no switcher and no "Dashboard" row. The only new visible part is the "Add orchestrator" button in the board header (Screen 5).
- The command palette entries "Manage boards" and "Go to Dashboard" are not visible chrome. They show only when the user opens the palette.
- The page title of a board-scoped page is the page name. When more than one board exists, the title is "<page name> · <board name>", for example "Board · Dispatch". With one board, the title stays "Board", as today.

## Screen 1: Boards page

### Purpose

The user sees all boards in one list, adds a board, edits a board and archives a board. LOCAL-85 and LOCAL-87 build this screen.

### Data

- Each board row of D-1: `key`, `name`, `repositories`, `archived`.
- Counts per board from the snapshot of that board: running sessions (cards with a live session, the cards that show the Live session chip of today), open groups (group cards not in Done) and the attention count (the number of items in the attention queue of Screen 4, Section 1).
- For the create form: the keys of all boards and the Linear team keys that the store knows (D-2).
- For the default board edit form: the `Config` field `workspaceRoot` and the store list `workspaceFolders` (D-1 amendment of 2026-10-06).

### Layout

- **1440 px:** the page body column of the design contract (720 px maximum width, centered). The page header holds the title "Boards" and the button "New board". Below it, one `table` with one row per board. The columns are Name, Key, Repositories, Running, Open groups, Attention and a row menu. Archived boards are in a `collapsible` section "Archived boards" below the table.
- **1024 px:** the same table. The Repositories cell shows the count ("2 repositories") in place of the folder names.
- **390 px:** no table. Each board is one `item` in a list: the name and the key on the first line, the three counts as `badge` parts on the second line, and the row menu at the right. The "New board" button stays in the page header.

## Screen 2: Board switcher

### Purpose

The user moves between boards from any page. The switcher shows the attention count of each board, so the user sees which board needs them. LOCAL-87 builds this screen.

### Data

- The board rows of D-1 that are not archived: `key` and `name`.
- The attention count of each board, as in Screen 1.
- The selected board: the `board` parameter of the current URL, else `LOCAL`.

### Layout

- **1440 px:** the sidebar header keeps the glyph and the wordmark. Below them, inside the header, one trigger button shows the name of the selected board and a chevron. The menu opens below the trigger, 240 px wide (`--nav-width`). The sidebar header grows by one row of 32 px when the switcher shows.
- **1024 px:** the same as 1440 px. When the sidebar is collapsed (56 px), the trigger shows the first two letters of the board key, and the menu opens to the right of the sidebar.
- **390 px:** the sidebar is a `sheet` as today. The trigger is the row below the wordmark in the sidebar header inside the sheet, full width. The menu opens below it, full width of the sheet.

### Parts

| Part                     | Primitive                 | Copy                                                                                                                                                   |
| ------------------------ | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Switcher trigger         | `dropdown-menu`, `button` | "<board name>". Accessible name "Switch board, current board <board name>". Collapsed sidebar: "<first two letters of the key>".                       |
| Board items              | `dropdown-menu`           | One item per board: "<board name>" and "<KEY>" in mono type. The selected board has a check glyph.                                                     |
| Attention count per item | `badge`                   | "<n>" when the count is above 0. Accessible name "<n> items need attention". No badge at 0.                                                            |
| Manage boards item       | `dropdown-menu`           | "Manage boards" after a separator. It opens `/boards`.                                                                                                 |
| Shortcut hint            | `kbd`                     | "B" beside the trigger tooltip, and in the cheat sheet row "Switch board" in the Global group. The cheat sheet row shows only when the switcher shows. |
| Trigger tooltip          | `tooltip`                 | "Switch board (B)"                                                                                                                                     |
| Palette entries          | `command`                 | One entry per board: "Switch to board <name>". The selected board has no entry. Group heading "Boards".                                                |

Rules:

- The switcher shows only when more than one board is not archived. With one board, the sidebar header is the header of today: the glyph and the wordmark.
- The shortcut is `b` with no modifier. No binding of today uses it. Mod+B toggles the sidebar (`src/web/components/ui/sidebar.tsx`), and Mod+Shift+B opens the bookmarks bar in Chrome, so the switcher uses no modifier. It is a global binding like `n`. It opens the switcher menu. It does nothing when the switcher does not show, when a text field has focus, or when a dialog or a menu is open.
- A board item goes to the same page on the other board: the route stays, and the `board` parameter changes. On `/boards` the route stays `/boards`.
- The palette entries show only when the switcher shows.

### States

| State   | What shows                                                                                                                                                 | Copy                                          |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| Empty   | One board only: no switcher, no palette entries, the header of today. A board list with no other board does not open.                                      | No copy. The switcher does not render.        |
| Loading | The switcher does not render until the board list loads, so a one-board user never sees it. The sidebar header shows the glyph and the wordmark, as today. | No copy.                                      |
| Error   | The switcher renders only when the URL `board` is not `LOCAL`. Then the trigger shows that key, and the menu holds one disabled item and a retry item.     | Item "Boards did not load." Item "Try again". |
| Stale   | The menu shows the last board list and the last counts. The attention badges are muted with the text style of muted text.                                  | Menu footer "Counts from <time>".             |

## Screen 3: Orchestrator panel

### Purpose

The user starts, stops and resumes the orchestrator of a board, watches its terminal, answers its decision items, edits the board policy and manages extra orchestrators. LOCAL-91 builds this screen.

### Data

- The main orchestrator of the board and its session: the session state of D-3 (with `stateReason` and `stateSince`), and the session id for the terminal path (`/sessions/<id>/terminal/`).
- The pending decision items of the board (D-3, D-7): the question, the options, the recommended option, the group and the owner orchestrator.
- The loops that only the user can resume: group sessions at `needs_input` with the `stateReason` `usage_stop` or `budget` (D-4).
- The board `policy` with the 10 fields of D-6.
- The board `orchestrators` of D-7: id, main flag, scope, policy override and session name, and the `ownerOrchestrator` of each group card.

### Layout

- **1440 px:** the `/board` content splits into a `resizable` panel group. The columns are on the left. The orchestrator panel is on the right: default width 36 percent, minimum 360 px (the minimum of the detail panel), with a drag handle between. The panel has a header row and four `tabs` below it: "Terminal", "Decisions", "Policy" and "Orchestrators". The board columns keep their own horizontal scroll.
- **1024 px:** the same panel group. The default width is 360 px, the minimum. The columns use the carousel mode of today when the space is narrow.
- **390 px:** the panel is a `sheet` from the right edge, full width. The header row is at the top of the sheet, the tabs below it. The close button of the sheet closes the panel and removes `panel=orchestrator` from the URL.

## Screen 4: Dashboard

### Purpose

The user sees, on one page, what needs them now and how each loop of the board progresses. The attention queue is first, so a stop does not wait unseen for 30 minutes or more (research F1, F3, F8). LOCAL-92 builds this screen.

### Data

- The route `/dashboard` with the `board` search parameter. With no parameter, the dashboard shows the default board (D-4).
- The group cards of the board with `loopProgress` (D-5): the units with their status, the current unit, the current phase of its phase count, the gate results and the failed attempts.

## Cross-screen rules

### Keyboard

- Each control on the five screens is reachable with Tab, in the visual order: page header, then the content top to bottom, then the panel.
- `b` opens the board switcher when it shows (Screen 2). The cheat sheet lists it in the Global group as "Switch board".
- Escape closes the top layer first: a menu, then a dialog, then the detail panel, then the orchestrator panel (at every width, when focus is in the panel).
- In a decision item, the option buttons are in their written order. The recommended mark does not move the option.
- The board keys of today (`j`, `k`, `h`, `l`, Enter and the digits) stay off while the orchestrator panel has focus, as they stay off while the detail panel is open.

### Focus

Each focusable part shows the focus outline of the design contract: 2 px solid `--accent`, offset 2 px. No ring and no box shadow (frontend rule 15).

### Colour-free reading

Each state on these screens has a glyph and a text label. Colour is an extra signal, never the only one. This applies to the session state badges, the segments of the progress bar, the ship states and the warning tone of the meters. A screen in grayscale shows the same information.

### Themes

Each screen works in the dark theme (the `:root` default of `tokens.css`) and the light theme (`:root[data-theme="light"]`). Each colour comes from a token. Text meets the contrast floor of the design contract in both themes.

### Session state labels

The 12 session states of D-3 have these labels and glyphs on every screen. The glyph is a `lucide-react` icon name.

| State                | Label                     | Glyph (lucide)              | Tone      |
| -------------------- | ------------------------- | --------------------------- | --------- |
| `working`            | "Working"                 | `Play`                      | neutral   |
| `idle`               | "Idle"                    | `Pause`                     | muted     |
| `needs_input`        | "Needs input"             | `MessageCircleQuestionMark` | attention |
| `permission_prompt`  | "Permission prompt"       | `ShieldQuestionMark`        | attention |
| `handoff_ready`      | "Handing off"             | `ArrowRightLeft`            | neutral   |

The tone maps to the `badge` tones of `src/web/components/ui/badge.tsx`: attention uses `tone="state"` with `stateColor="var(--col-needs-input)"` (the label mixes 35 percent of the state colour with `--text`, so it meets the contrast floor), error uses `danger`, success uses `success`, muted uses `neutral`, and neutral uses the `outline` variant. ## Changes

### 2026-10-07 (LOCAL-92)

This entry adds to the screens above. It does not change the text of an earlier section.

- **Screen 4, Section 2 (R-12).** Each row gains two neutral badges after the state badge. "Session <time>" shows the age of the active session. The time-left badge shows "About <time> left", "At least <time> left" when a later unit has no PRD, or "Estimate after 2 gates" when fewer than two gates passed.
- **Screen 4, Section 2 label (U1-11).** A loop with all units shipped shows "<n> of <n> units shipped". A loop between units shows "<done> of <total> units built, unit <n> not started".
- **Screen 4, Section 3 (U1-10).** The section gains a collapsible "Show cards" list. A group select and a column select filter the list.
- **Screen 4, Section 4 (U1-09).** The section gains an actor select with the options All, Orchestrator, Supervisor and You, and a group select.
- **Screen 1 (R-16).** The boards table gains a "Loops" column after "Attention". Each running loop shows "<group id> <percent>%". The cell shows at most three loops, then "+<n> more". A board with no running loop shows "0". From 768 px to 1279 px, the cell shows only the number of running loops, as the Repositories cell shows a count (U1-30). Below 768 px, each board item gains one more badge line with the same text.
